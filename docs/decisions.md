# 決定の記録

**母集団（`sources/`）と辞書（`dict/`）を変えると、過去の分析と比較できなくなる。**
だから「いつ・何を・なぜ」を必ずここに1行足す。図の解釈で「この日から傾向が変わった」と
見えたとき、実は設定を変えただけ、という事故を防ぐための台帳。

書式: `## YYYY-MM-DD` の下に、変更したものと理由。**過去のエントリは書き換えない。**

---

## 2026-08-15 — 初期構築

### 母集団を Googleニュース検索RSS 7本に決めた

`sources/gnews_*.yaml`。検索語は 文化庁 / 文化政策 / 文化財(保存・修理・防災) /
文化観光・日本遺産 / 博物館(学芸員・博物館法・収蔵) / 劇場・音楽堂・美術館(助成・補助金・指定管理) /
文化関連法令。

**なぜ Googleアラートでなく Googleニュース検索なのか**: アラートは登録に人手が要り、
アカウントに紐づく。Googleニュース検索RSS は URL を組み立てるだけで、認証もアカウントも
不要。監視対象の追加が「`sources/` に YAML を1枚置く」作業になり、リポジトリから
設定が見える。要約が欲しくなったらアラートの RSS も同じ `kind: rss` で読める。

**なぜ RSS が無い文化庁を後回しにしたか**: HTMLスクレイプはサイト改修で壊れるので、
`fixtures/` の回帰テストとセットで実装したい。Googleニュース経由で文化庁の話題自体は
入ってくるので急がない。

### 報道記事の本文は保存しないと決めた

`tier: secondary` は見出し + フィードの要約 + URL のみ。報道記事の全文をリポジトリに
置くと再配布にあたる（リポジトリは 2026-08-15 に public にした）。
官公庁の公表資料（`tier: primary`）は本文まで保存してよい。

**この判断はコードで強制している**（`collect._should_fetch_body`）。設定に
`fetch_body: true` と書いても無視される。人間の注意力に頼ると必ず破られるため。

**分析上の損失は小さい**と判断した。見出しは本文より情報密度が高く、共起の質にはむしろ
見出しが効く。ただし文脈が見えなくなる制約は残る（handoff.md §5-②）。

### 共起の重みを NPMI にした

生の共起回数を重みにすると「文化庁」が全ノードと繋がって毛玉になる。
NPMI は「他の語と比べてどれだけ一緒に出やすいか」を見るので、高頻度語が支配しない。

### 共起の単位を「文」にした

記事単位だと「同じ記事に出た」だけで繋がり、密になりすぎる。
※ 現在のコーパスは見出しのみなので 1記事 ≒ 1文で、この選択は実質効いていない。

### 閾値: min_df=2 → 4、min_cooc=2 → 3、min_npmi=0.20 → 0.25

**同日中に変更。** 記事390件で初めて実データの図を見たところ、NPMI 上位を単発記事の
2語ペアが独占していた（1本の記事にしか出ない2語は必ず NPMI = 1.0 になる）。
実例:「AGU — ライフ」「トレード — 総合文化政策学部フェア」。

記事が数千件規模になったら、`min_df` はさらに上げる余地がある。

### 検索語「文化政策」から学部名を除外

`-総合文化政策学部 -学部生 -オープンキャンパス` を追加。青山学院大学の学部名を
大量に拾っていた。**母集団が変わる変更**なので、この日以前と以後で「文化政策」由来の
記事の性質が違う。

### 辞書の初期セット

政策・制度 43件、施設・組織 40件。実データを見て以下を追加した:
文化財保存活用地域計画 / 文化観光拠点施設 / 紡ぐプロジェクト。

**エイリアスは長い順に当てる。**「国立劇場おきなわ」が「国立劇場」に食われないため。
短くて汎用的なエイリアス（例:「基本法」）は登録しない。

### 除外語 180語

一般的な機能語に加えて、実データで浮いた無内容語（令和・平成・今年度…）と、
見出しに混ざるサイトの定型（お知らせ・ニュース・報道発表・プレスリリース…）を追加。
**「支援」「予算」「補助金」「助成」は入れていない** — 文化政策の言説では意味のある語。

### 色は2色 + 中立グレーに絞った

語は中立グレー、色を持つのは文化施設（青）と政策・制度（橙）だけ。
語ノードが全体の大半を占める「地」なので、ここに色を使うと本当に見たい施設・政策が
埋もれる。種別は形（●■◆▲）でも区別＝色だけに意味を載せない。
light/dark 両モードで CVD 分離とコントラストの検証済み（`pipeline/style.py`）。

### リポジトリを public にした

Gephi Lite に URL を渡して直接開けるようにするため。
`articles/` の中身は見出し・日付・媒体名・URL のみで、報道記事の本文は入っていない
（上の tier の判断）ため、公開して問題ないと判断した。

## 2026-08-15（2） — 一次情報の本文を取り込む / 記事一覧を出す

### 文化庁と文部科学省を母集団に加えた（**母集団が変わる変更**）

`sources/bunka_hodo.yaml`（文化庁 広報・報道・お知らせ、`kind: html_list`）と
`sources/mext_hodo.yaml`（文部科学省 新着情報 RDF）を `enabled: true` にした。
どちらも `tier: primary` なので**本文まで保存する**。

**この日以前と以後で、コーパスの性質が変わる。** 以前は報道の見出しだけ（1記事 ≒ 1文）、
以後は官公庁の公表資料の本文（1記事 = 数十文）が混ざる。時系列で比較するときは
必ずこの境目を意識すること。

- 文化庁: RSS配信が無いので一覧ページのリンクを拾う。**CSSセレクタではなく
  href の正規表現（`link_pattern`）で選ぶ**。セレクタはサイト改修で必ず壊れるが、
  URLの形はそう変わらない。日付はリンクの前後の文脈から探す（handoff §4-⑧）
- 文部科学省: `/rss/rss.xml` は 404 だった。実際の配信は
  `https://www.mext.go.jp/b_menu/news/index.rdf`（2026-08-15 に probe で確認）

### 本文は 20000 字で打ち切る

官公庁のページは関連リンクや添付の説明で長くなる。1記事が共起単位を数百持つと、
その1記事だけで母集団が歪む（df も NPMI も、1記事の中の繰り返しに引きずられる）。

### 閾値は**まだ**変えていない

`min_df: 4` / `min_cooc: 3` / `min_npmi: 0.25` は見出しだけの390件に合わせた値。
本文が入ると分布が変わるので調整が要るが、**実際のデータを見てから**にする。
先に `dict/stopwords.txt` へ官公庁ページの定型句を足すこと（handoff §5-②）。

### 記事一覧（`out/articles.html` / `articles.csv`）を出すことにした

図だけを見て記事を読まないと、共起の意味を取り違える。「日本遺産 — 認定」が
何を指しているかは、記事を1本読めば分かる。ノードと記事を相互参照できるようにした
（図でノードを選ぶ → その語が出た記事 → 一覧で絞り込み → 図に戻る）。

出力を増やしただけで、母集団・辞書・閾値は変えていない。**図は1本の線も変わらない。**

## 記録すべき変更の種類

- `sources/*.yaml` の追加・削除・**検索語の変更**（母集団が変わる）
- `dict/*.yaml` のエンティティ追加（解像度が変わる。**id の変更は禁止**）
- `dict/stopwords.txt` の変更
- `config.yaml` の閾値・`unit`・`trend` の変更
- 記事の一括削除（例: 古い記事の間引き）

記録しなくてよい変更: コードのリファクタ、バグ修正、出力形式の追加、色の調整。
